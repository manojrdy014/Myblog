Big O Notation: My Journey to Understanding Algorithm Efficiency

Introduction: Why DS&A Felt Hard at First (and Why It Matters)

When I first started learning Data Structures and Algorithms (DS&A), I thought programming was mainly about making code work correctly. If the output was right, I assumed the solution was good enough. But soon, I realized something important: not all correct solutions are efficient.

That’s when I encountered Big O notation—a concept that completely changed how I think about coding. At first, it felt abstract and mathematical, but over time, I began to see why universities like Lewis University make DS&A a required course. Big O notation helps us understand how algorithms perform as data grows, which is essential in real-world software development.

In this post, I’ll explain Big O notation in a simple way, share examples, and reflect on my learning experience with DS&A.

What Is Big O Notation?

Big O notation describes how fast an algorithm grows in terms of time or memory when the input size increases. Instead of asking how fast a program runs on a specific computer, Big O focuses on how the algorithm behaves as the input becomes very large.

Visualizing Big O Growth Rates:

  • O(1) - Constant Time
  • O(log n) - Logarithmic Time
  • O(n) - Linear Time
  • O(n log n) - Linearithmic Time
  • O(n^2) - Quadratic Time

Example 1: Linear Search – O(n)

A linear search checks each element one by one until it finds the target value.

def linear_search(arr, target):
    for x in arr:
        if x == target:
            return True
    return False

If the list has n elements, the algorithm may check all n elements in the worst case.

Example 2: Binary Search – O(log n)

Binary search works on sorted data and repeatedly divides the search space in half, making it much faster for large datasets.

def binary_search(arr, target):
    low, high = 0, len(arr) - 1
    while low <= high:
        mid = (low + high) // 2
        if arr[mid] == target:
            return True
        elif arr[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return False

Why Big O Notation Is Important?

  1. Real-World Applications 🌍
    Big O impacts:
    • Search engines (fast search results)
    • Databases (query performance)
    • Social media (recommendation systems)
    • Mobile apps (smooth user experience)
  2. Better Decision-Making
    Two algorithms may solve the same problem, but Big O helps us choose the better one.
  3. Interview and Career Relevance 💼
    Many technical interviews focus on algorithm efficiency, not just correctness.

Best Practices and Common Mistakes

Best practices include analyzing both time and space complexity and comparing multiple solutions. Common mistakes include ignoring efficiency and misunderstanding Big O as exact execution time.

Personal Reflection

Learning DS&A was challenging at first, but it significantly improved my problem-solving skills. Big O notation helped me think more deeply about algorithms and write more efficient code. I now see DS&A as a foundational skill for any computer science career.

Conclusion

Big O notation is a powerful tool that helps us understand algorithm efficiency and scalability. Mastering this concept is essential for becoming a better programmer and problem solver.

📝 Week-5 Array-Based Sequences

Implementing a Dynamic Array in Python:A Hands-On Exploration

One of the simplest data structures in computer science is dynamic arrays, which however are usually abstract due to the high-level languages such as Python, which manage this data structure. This post is a discussion on the functionality of a dynamic array by trying to create a basic implementation of one using Python. This activity made me more familiar with the concept of memory allocation, resizing policies and performance trade-offs that are essential in data structures and algorithms.

Part 1: Implementing a Dynamic Array

The included list type in python is already a dynamically growing array, however, to get a feel of what is occurring behind the curtain I wrote a basic implementation in a simple form with the ctypes module. This enabled me to use low-level arrays like they are handled by C.

The dynamic array maintains:

  • A capacity (allocated size)
  • A size (number of elements stored)
  • A raw array to hold elements (the underlying data structure)

When the array reaches its capacity, it resizes by allocating a new array with larger capacity and copying existing elements.

Code Implementation: 

import ctypes

class DynamicArray:
    def __init__(self):
        self.size = 0
        self.capacity = 1
        self.array = self._make_array(self.capacity)

    def _make_array(self, capacity):
        return (capacity * ctypes.py_object)()

    def get(self, index):
        if not 0 <= index < self.size:
            raise IndexError("Index out of bounds")
        return self.array[index]

    def append(self, value):
        if self.size == self.capacity:
            self._resize(2 * self.capacity)
        self.array[self.size] = value
        self.size += 1

    def insert(self, index, value):
        if not 0 <= index <= self.size:
            raise IndexError("Index out of bounds")
        if self.size == self.capacity:
            self._resize(2 * self.capacity)
        for i in range(self.size, index, -1):
            self.array[i] = self.array[i - 1]
        self.array[index] = value
        self.size += 1

    def delete(self, index):
        if not 0 <= index < self.size:
            raise IndexError("Index out of bounds")
        for i in range(index, self.size - 1):
            self.array[i] = self.array[i + 1]
        self.array[self.size - 1] = None
        self.size -= 1

    def _resize(self, new_capacity):
        new_array = self._make_array(new_capacity)
        for i in range(self.size):
            new_array[i] = self.array[i]
        self.array = new_array
        self.capacity = new_capacity

**Note: This implementation supports append(), insert(), delete(), get(), and automatic resizing.

Part 2: Reflection on the Experience

Understanding Dynamic Arrays

Flexibility is the key strength of dynamic arrays in comparison with the static arrays. The size of the static arrays is fixed and thus it may eat up unnecessary memory or may overflow. Dynamic arrays expand when required giving a trade-off between memory efficiency and speed.

The built-in list of Python is a dynamic array that is highly optimized. Python lists do not grow on a case-by-case basis. It instead pre-allocates additional space, which minimises the number of expensive resizes.

Resizing Under the hood resizing just requires acquiring a new block of memory and moving references to the new array, which is exactly what this implementation simulates.

Implementation Challenges

Resizing was the most difficult aspect to deal with. Failure to replicate elements or update capacity will result in subtle bugs. Relocation of elements during the insert and delete operations was also prone to errors and it was also my realization that a lot of work is abstracted out by Python.

Although the implemented functions are functional, they are not as efficient as Python list. Considering an example, the downsizing of the array is not supported, and the optimization of memory is minimal. But it was not to be perfect but to understand.

Big O Considerations

Dynamically maintained arrays offer O(1) get time complexity. Appendix is normally O(1), but during resizing, it is O(n). Nevertheless, due to the low frequency of resizing, amortized cost of append is O(1).

Middle deletions and insertions require O(n) time as a result of shifting elements. Conversely, a linked list can be desirable when there is a need to do numerous insertions or deletions of an element particularly at the start of the structure. Linked lists however compromise random access, which is constant.

Personal Reflection

This task has greatly enriched my knowledge on dynamic array. The one-manual implementation of resizing converted the idea into a practical process that has memory allocation and copying expenses.

When describing dynamic arrays to an unprocessed user, I would describe them as a larger notebook: once you run out of pages, you get another larger notebook and transfer your notes to it. This replication is time-consuming though the frequency of this replication is low and therefore the average cost remains low.

Overall, this practical use case cemented the importance of dynamic arrays as a potent and commonly used data structure- and why the realization of everything that goes on behind the scenes is important to create an efficient code.

PART-1: Modified Singly Linkedlist:

    class SinglyLinkedList:
    class Node:
        def __init__(self, data):
            self.data = data
            self.next = None
        
    def __init__(self):
        self.head = None
        self.tail = None   # Added for O(1) insertion at end
        self.size = 0

    def __len__(self):
        return self.size

    def is_empty(self):
        return self.head is None
    
    def add_first(self, data):
        new_node = self.Node(data)
        new_node.next = self.head
        self.head = new_node

        if self.tail is None:  
            self.tail = new_node

        self.size += 1

    def add_last(self, data):   
        new_node = self.Node(data)

        if self.head is None: 
            self.head = new_node
            self.tail = new_node
        else:
            self.tail.next = new_node
            self.tail = new_node

        self.size += 1

    def delete(self, data):
        if self.head is None:
            return

        # If head needs to be deleted
        if self.head.data == data:
            self.head = self.head.next
            if self.head is None:  
                self.tail = None
            self.size -= 1
            return

        current = self.head
        while current.next:
            if current.next.data == data:
                if current.next == self.tail:  
                    self.tail = current
                current.next = current.next.next
                self.size -= 1
                return
            current = current.next

    def remove_first(self):
        if self.head is None:
            return

        self.head = self.head.next

        if self.head is None:  # List became empty
            self.tail = None

        self.size -= 1

    def display(self):
        current = self.head
        while current:
            print(current.data, end=' -> ')
            current = current.next
        print('None')

PART-2: Doubly Linkedlist Implementation:

    class DoublyLinkedList:
    class Node:
        def __init__(self, data):
            self.data = data
            self.next = None
            self.prev = None

    def __init__(self):
        self.head = None
        self.tail = None
        self.size = 0

    def is_empty(self):
        return self.head is None

    def add_first(self, data):
        new_node = self.Node(data)

        if self.head is None:
            self.head = self.tail = new_node
        else:
            new_node.next = self.head
            self.head.prev = new_node
            self.head = new_node

        self.size += 1
        print("Inserted at beginning.")

    def add_last(self, data):
        new_node = self.Node(data)

        if self.tail is None:
            self.head = self.tail = new_node
        else:
            self.tail.next = new_node
            new_node.prev = self.tail
            self.tail = new_node

        self.size += 1
        print("Inserted at end.")

    def remove_first(self):
        if self.head is None:
            print("List is empty.")
            return

        self.head = self.head.next

        if self.head:
            self.head.prev = None
        else:
            self.tail = None

        self.size -= 1
        print("First node removed.")

    def remove_last(self):
        if self.tail is None:
            print("List is empty.")
            return

        self.tail = self.tail.prev

        if self.tail:
            self.tail.next = None
        else:
            self.head = None

        self.size -= 1
        print("Last node removed.")

    def delete(self, data):
        if self.head is None:
            print("List is empty.")
            return

        current = self.head

        while current:
            if current.data == data:
                # If node is head
                if current.prev is None:
                    self.remove_first()
                # If node is tail
                elif current.next is None:
                    self.remove_last()
                else:
                    current.prev.next = current.next
                    current.next.prev = current.prev
                    self.size -= 1
                    print("Node deleted.")
                return
            current = current.next

        print("Value not found.")

    def display_forward(self):
        if self.head is None:
            print("List is empty.")
            return

        current = self.head
        while current:
            print(current.data, end=" <-> ")
            current = current.next
        print("None")

    def display_backward(self):
        if self.tail is None:
            print("List is empty.")
            return

        current = self.tail
        while current:
            print(current.data, end=" <-> ")
            current = current.prev
        print("None")

PART-3: Reflection on Linked Lists

Understanding Linked Lists:

Linked lists have many differences with arrays in terms of data storage and data management. Whereas arrays occupy consecutive memory addresses, a linked list comprises of nodes which are linked by pointers and therefore dynamic memory allocation is made possible. This increases the flexibility of linked lists, particularly where list insertions and removals have to be done frequently, since this can be efficiently done without changing the position of the elements. Contrary to this, arrays offer quick random access hence they are more suitable when indexing is necessary. I would prefer a linked list to an array in situations where the ability to expand and update the array is of greater significance than directly accessing the data.

Implementation Challenges:

I used singly and doubly linked lists in this assignment. A singly linked list merely has a pointer to the following node and as such is memory-efficient but restricted to exploration (only forward). Instead, a doubly linked list has both a next and a previous pointer and can be traversed along a direction, and can also be deleted easily. Such an added capability however would be at the expense of increased memory consumption and a little more complicated implementation. Among the main changes that I have done was the introduction of the add last technique in O 1 time that utilized a tail pointer that does not involve the whole list.

Personal Reflection:

The hardest aspect of this exercise was keeping the correct pointer updates in particular in the edge cases like empty list or removing of the last node. To keep the add last() function in constant time, it was designed carefully especially in updating the tail reference. With this practical application, I was able to better understand the internal operations of linked lists and the influence of pointer manipulation on performance. One way of explaining linked lists to a beginner is that they are a chain of connected items, where one item points to the next and therefore is flexible but needs intricate navigation as opposed to arrays.

📝 Week-10 Trees

Data structures form a core aspect of computer science in that they specify the manner in which data is structured, stored and retrieved in an efficient manner. The tree is one of the most common structures to be introduced in courses on programming and is commonly used in searching, sorting, databases, and file systems. To complete this post, I have watched a YouTube video that describes the fundamentals of tree data structures and discusses its effectiveness in teaching the idea.

Video reviewed: “Binary Trees in 5 Minutes” by CS Dojo https://www.youtube.com/watch?v=H5JubkIy_p8 Overview of the Video.

The video presents the element of a tree data structure with the specific attention paid to binary trees. It starts with an explanation of the composition of trees as having nodes that are linked in a hierarchical manner. Some of the important terminology that are explained by the presenter include root node, parent, child and leaf nodes that are fundamental in understanding trees.

The video next makes a short overview on how binary trees operate, with each node having a maximum of two children (left and right). It also describes some practical applications of trees, such as searching algorithms, and modeling hierarchical data structures such as file systems.

What Works Well?

Simplicity and clarity is one of the strengths of the video. The presenter explains the subject with simple diagrams and explanations and it is easier to be understood by beginners. The time flow is also appropriate- the video does not present a lot of technical information at once as the concepts are introduced step by step.

The second strength lies in the visual interpretation of nodes and branches that enable viewers to grasp the process of tree structures within a short period of time. The diagrams are very helpful in understanding since trees are hard to imagine when they are just explained orally.

Could Be Better:

Although the video is good as an intro, it can be enhanced with more real-world examples or mini-coding demonstrations. It would be beneficial to demonstrate how a binary tree could be coded in a computer programming language like Python to make viewers relate the theoretical understanding to real-world programming.

Also, the video briefly refers to the concept of tree traversal but does not elaborate on it. The explanation would be more complete by elaborating on the traversal techniques like in-order, pre-order and post-order traversal.

My Commentary on Trees:

In computer science, tree data structures are of paramount importance as it allows effective search and organization of data. In a binary search tree (BST) as an example, when a tree is balanced, binary search tree operations such as deletion, insertion, and searching are much faster than in simple lists. There are also numerous applications of trees in the real world like databases, compilers and artificial intelligence systems.

Learning about trees also creates a base upon which more complex structures like heaps, AVL trees and B-trees; which are applications of these in priority queues, indexing systems and large scale storage systems.

YouTube Effectiveness in Learning Data Structures:

YouTube can be an excellent resource in learning technical concepts such as data structures since it has visualization, animation and step wise explanation. Most learners find it easier to learn complex structures when they have the opportunity to view them in their visual form as opposed to reading about them in the textbooks.

YouTube, however, is not the one that should replace formal learning; it should be used as supplement instead. Videos can make things easier to understand and might omit more rigorous theoretical explanations or analysis of algorithms. Hence, a combination of video learning with textbooks, code practice and classroom training is the most effective.

On the whole, this video is a concise and easy to understand introduction to tree data structures, and is a good place to start as a beginner in learning this significant concept.
